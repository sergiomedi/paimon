This set exists to be run **once**, after a change, and never iterated against.
This is that run. Both systems answered the same ten tasks in the same process,
against the same twelve documents, with nothing differing but the layout.

## The change did what it was aimed at

The Step 2 report found the `tool-lines` investigator withdrawing 37 of 125
answerable attempts for want of a resolvable citation, while two simpler
systems managed 250 of 250. The layout change was aimed at exactly that, and on
the held-out set it moved exactly that:

| | `investigator` (numbered-sources) | `investigator-v1` (tool-lines) |
|---|---|---|
| withdrawn — `no_material` | **6 / 50** | 22 / 50 |
| answerable attempts citing nothing | **14 / 45** | 22 / 45 |
| outcome correct | **36 / 50** | 28 / 50 |
| citation precision 1.0 | **36 / 50** | 28 / 50 |

Withdrawals fell by more than two thirds and eight more attempts answered or
refused correctly. The mechanism the change targeted is better.

Paired, task by task:

| | difference in pass rate | p | |
|---|---|---|---|
| investigator − investigator-v1 | **+2.0%** [−34.0%, +38.0%] | 0.892 | not distinguishable from noise |

Two tasks changed hands and cancelled: `h008` (one-hop) went 0/5 → 5/5, `h003`
(multi-hop) went 4/5 → 0/5. Everything else scored identically. **On ten tasks
this set cannot separate the two layouts**, and the interval is wide enough to
contain a large improvement and a large regression alike.

## Why the improvement did not reach the score

`passed` requires three things at once: the right outcome, **full** support
coverage, and citation precision of 1.0. Decomposed over all 50 attempts:

| | outcome correct | full support coverage | full citation precision | **passed** |
|---|---|---|---|---|
| `investigator` | 36 / 50 | **16 / 50** | 36 / 50 | **16 / 50** |
| `investigator-v1` | 28 / 50 | **15 / 50** | 28 / 50 | **15 / 50** |

Coverage is the binding constraint, it barely moved, and `passed` tracks it
almost exactly. The reason is in the row that did not change at all:

> **Tool calls per run: 1.00. In every one of the 100 runs, both layouts, the
> model searched once and stopped.**

All six multi-hop tasks need two distinct documents. Distinct documents cited:

| | 0 documents | 1 document | 2 documents |
|---|---|---|---|
| `investigator` | 19 | 20 | **11** |
| `investigator-v1` | 27 | 13 | **10** |

The new layout nearly halves the attempts that cite nothing — 19 against 27 —
and converts almost all of that into citing *one* document. Reaching two is
unchanged (11 against 10), because a second document can only appear when a
single search happened to retrieve chunks from both. `h003` is that in
miniature: both layouts answered "41" correctly, and `v1` scored because its
one search happened to return a `platform-limits` chunk on four trials out of
five while the other's did not. That is retrieval luck, not a property of the
layout.

## What this says about the Step 2 reading

Step 2 concluded that the investigator's failures were "not mostly about
hopping" — 1.093 tool calls per run, but 18 of 24 one-hop and exact-identifier
failures were withdrawals, pointing at presentation rather than at the loop.

**That was half right, and the half that was wrong is the important one.**
Presentation did explain the withdrawals: fixing it cut them from 22/50 to
6/50 here. But fixing them bought no measurable task success, because the
agent still takes exactly one hop, and one hop cannot cover two documents
except by accident. The hopping limitation was real and is now the binding
constraint, with the presentation problem no longer hiding it.

## What cannot be concluded

- **Ten tasks.** Every interval here is enormous; ±39.7% on pass@1 is not a
  measurement of a difference, it is a statement that ten tasks cannot find one.
- **Six multi-hop tasks**, and the multi-hop figures move by whole tasks.
  `investigator` scoring 3.3% against 16.7% is one task's worth of difference.
- **The out-of-corpus column is one task.** It is reported because leaving it
  out would hide a regression, not because one task measures refusal.
- The tasks and the corpus were written by the same author who made the change.
  What the set still buys is that no per-task result from it informed the
  change: the change was committed before this set was ever run.
- The refusal judge is `phi4`, whose local calibration was declared
  **unmeasurable** for the out-of-corpus and injection columns under the rule
  fixed before that validation. That verdict stands here too.

## The honest summary

The change is kept. It is better on every mechanism it was meant to fix and is
not worse on anything measured. But **it is not shown to make the agent better
at the task**, and the held-out set was built precisely so that claim could not
be made from the set that suggested the change. The measured answer to "did the
fix work" is: the fix worked, the agent did not improve, and the reason is a
limitation the fix was never aimed at.
